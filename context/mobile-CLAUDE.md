# Cipher Duel — Android

Kotlin Multiplatform 2.4 + Compose Multiplatform 1.12 (Android and iOS from one codebase), AGP 9.4, Gradle 9.8,
minSdk/targetSdk see `app/build.gradle.kts`. The Android SDK is installed without Android Studio. There is no KVM, so no
emulator either: the UI is checked with Paparazzi screenshot tests. There is no Mac: the iOS code is compiled here
(`kotlin.native.enableKlibsCrossCompilation`), while linking the framework and building the app happen only on a Mac
(Codemagic, `../codemagic.yaml`).

## Modules
- `:core` — KMP (jvm + iOS), pure Kotlin: `Code`, `Feedback`, `Duel` (last-guess rule, draw, `timeOut()`),
  `Seat` ONE/TWO, `RpsChoice`, `TurnTimer.OPTIONS`, `ai/ComputerBreaker` (difficulty levels), `history/GameRecord`.
  JUnit 5 tests in `jvmTest`, including `SharedVectorsTest` (reads `../shared/rules-test-vectors.json`).
  Common Kotlin only: no `System`, `Math`, `java.*` (there are `monotonicNanos()`, `kotlin.math`, `kotlin.time`).
- `:shared` — KMP library (`com.android.kotlin.multiplatform.library`): all UI and data, package `com.cipherduel`.
  `commonMain` — screens, ViewModels, storage; `androidMain` / `iosMain` — platform `actual`s (see below).
  Strings — `src/commonMain/composeResources/values{,-uk}/strings.xml`, class `com.cipherduel.resources.Res`
  (each key is imported separately: `import com.cipherduel.resources.menu_title`). Formats only with an index (`%1$d`),
  apostrophes without `\'`. For iOS — the `Shared` framework (static).
- `:app` — Android shell: `MainActivity` (calls `AppGraph.init`), icon, manifest; all app tests live here too.
- `iosApp/` — iOS shell: SwiftUI shows `MainViewControllerKt.MainViewController()`, `GoogleSignInBridge.swift`.
  The Xcode project is generated by XcodeGen from `iosApp/project.yml` (no `.xcodeproj` in git); a Gradle phase builds `:shared`.

## Platform code (`com.cipherduel.platform`)
- `elapsedRealtime()` — SystemClock / CLOCK_MONOTONIC; `httpEngine()` — OkHttp / Darwin (explicit, because ServiceLoader breaks with R8).
- `currentLocaleTag()`, `setAppLanguage()` — Android: AppCompatDelegate (the Activity is recreated);
  iOS: `AppleLanguages` + `AppLanguage.override`, and `CipherDuelApp` rebuilds the UI via `key()`.
- `formatDate()`, `rememberShareText()`, `rememberGoogleSignIn()` (Android — Credential Manager;
  iOS — Swift via `IosBridge.googleSignIn`), `TokenVault` (Android Keystore / iOS Keychain).
- `data/AppGraph` — single instances of `api`, `settings` (DataStore at the same path it had on Android),
  `accounts`, `history`, `achievements`. Screens take storage from here, not from `Context`.
- `AppConfig` — API/WS addresses and the Google Web Client ID (instead of BuildConfig).
- `ui/components/AppMessages` — a short message above all screens (instead of Toast).
- Links `https://<domain>/f/{friend code}` and `/r/{room code}` (+ `cipherduel://…`): Android — intent-filter
  with `autoVerify` in the manifest, `MainActivity` → `AppGraph.openLink()`; iOS — the `cipherduel` scheme in `Info.plist`,
  `onOpenURL` → `IosBridge.openUrl()` (universal links — after the Apple account, they need a Team ID). `data/DeepLinks` parses
  the URL, `AppGraph.pendingLink` waits until the online lobby has an account.

## UI and data architecture
- `ui/CipherDuelApp.kt` — Navigation Compose routes (multiplatform, `Routes`); game arguments are passed in the route and read from `SavedStateHandle`.
- `ui/game/` — one game screen shared by all modes:
  - `GameUiState` + `Phase` (SECRET, HANDOFF, WAITING, RPS, PLAYING, FINISHED); `online: OnlineInfo?` only for online games;
  - `GameActions` — the actions interface; implemented by `GameViewModel` (local modes) and `OnlineGameViewModel`;
  - `GameContent` — the screen scaffold with slots (`topBarActions`, `banner`, `secretHeader`, `waitingContent`, `resultExtra`, `overlay`);
    "Back" — `NavigationBackHandler` (navigationevent): on Android the dispatcher is registered by `MainActivity`
    (AppCompatActivity doesn't do it itself — without it the game screen crashes), in the gallery outside an Activity — by `Gallery`;
  - `DuelBoard`, `RpsPhase`, `ResultDialog`.
- `ui/online/` — lobby (`OnlineLobbyViewModel`) and game (`OnlineGameViewModel`): turns `RoomStateDto` into `GameUiState`,
  drops states older than `version`, after the game ends writes to history and clears the saved session.
- `data/online/` — `OnlineApi` (Ktor + kotlinx.serialization): REST for actions, `roomUpdates()` — WebSocket (`AppConfig.WS_URL`)
  as `Flow<RoomStateDto>`; close codes 4401/4404 → `ApiException` 401/404. DTOs match `server/API.md`.
  `OnlineGameViewModel.listen()` keeps the socket until the game ends and reconnects with a 1–5 s pause.
- `data/AccountRepository` — guest account (nickname), profile, rooms with the session token; 401 `not_signed_in` clears the token.
  The session token goes through `TokenVault`. Google on Android — Credential Manager with `AppConfig.GOOGLE_WEB_CLIENT_ID`; the
  Android client in Google Cloud is bound to the release key's SHA-1, so sign-in works only in an APK signed with it. On iOS — the
  GoogleSignIn SDK: `GIDClientID` (iOS client) and `GIDServerClientID` (Web client).
  R8 rule for Play Services — `app/proguard-rules.pro`. Screens: `ui/online/OnlineLobbyScreen` (nickname / lobby
  with unfinished games), `ui/profile/`.
- Achievements: rules in `:core` `achievements/` (`Achievements.ALL` — a counter + tier thresholds; a new tier = a new number
  in `tiers`), `AchievementBook` — counting, protection from duplicates and merging with the server. `data/AchievementRepository` —
  `achievements.json` + account sync (`/api/me/achievements`, counters add up). Events are sent by
  `GameViewModel` (games against the computer only) and `OnlineGameViewModel`; two-player games don't count. Texts — `ui/achievements/AchievementTexts.kt`
  and `ach_*` strings; notification — `AchievementBanner` above the NavHost; medallions — `AchievementIcons.kt` (drawn on Canvas).
- Friends: `data/FriendsHub` (`AppGraph.friends`) — list and invitations; while the app is on screen
  (`repeatOnLifecycle(STARTED)` in `CipherDuelApp`), it keeps the `/ws/me` socket (`OnlineApi.friendUpdates`). New invitations —
  a pop-up `ui/friends/InviteBanner` above the NavHost. Screen `ui/friends/FriendsScreen` (link, nickname, requests, "Invite");
  in the lobby — invitations and "Invite a friend" (a room with `friendId`); in the result dialog — "Add friend" (`roomCode`).
  No push notifications yet: invitations to a closed app are visible in the lobby.
- Emotes in online games: `ui/emotes/` — `Emote` (id = `server/src/Game/Emote.php`, checked by `EmotesTest`), drawings and animations
  on Canvas (`EmoteIcons`), `EmoteBubble` / `EmotePanel`. The room socket gives `RoomEvent.State` / `RoomEvent.Emote`;
  `OnlineGameViewModel.sendEmote` (2.5 s cooldown) puts `myEmote` / `opponentEmote` into `OnlineInfo`, the bubble hides itself
  (the `overlay` slot in `GameContent`). A new emote goes both into the server enum and here.
- Avatars: `ui/avatars/` — `Avatar` (id = `server/src/Game/Avatar.php`, checked by `AvatarsTest`; unknown → bull),
  drawings on Canvas (`AvatarImage`), `AvatarPicker` in the profile (changes at once, `PATCH /me {avatar}`), `AvatarWithStatus` in friend lists.
  Online — `OnlineInfo.myAvatar` / `opponentAvatar` (attempt panels, RPS). No custom pictures, on purpose.
- Code/guess input — `ui/game/CodeInput` (position → digit + cursor): tapping a cell (`GameActions.selectSlot`) chooses
  where the digit goes; "erase" clears the selected cell or the nearest one to the left. Both ViewModels only call its methods.
  A long press on a filled guess cell pins the digit (`togglePin`, green with a pin): it can't be changed or erased,
  and `nextTurn()` carries pinned digits into the next turn. `GameViewModel` keeps them per player (`pins`), online —
  in `input` itself. They live while the game is open. The `PinHint` hint (`LocalPinHint`, the `pin_hint_seen` flag in DataStore)
  disappears for good after the first pin.
- History: `data/HistoryRepository` — `history.json` + `history_sync.json` (ids not sent yet, deferred clearing);
  with an account, after sync history = account + unsent games (`HistoryMerge` in core).
- The result dialog is a `ModalCard` (a screen layer, not an AlertDialog), so the achievements banner is above the dim.
  Screenshot tests enable `LocalInspectionMode`, so entry animations are in their final state there.
- `data/SettingsRepository` — DataStore: game settings, unfinished online session, account token (`TokenVault`).
  `data/HistoryRepository` — `history.json`, up to 200 games. Files — `data/TextFile` (kotlinx-io, atomic writes).
- `ui/components/` — locks, keypad, code cells, attempt panels, `TurnTimerPicker` / `TimerChip`.
- Timers count from `elapsedRealtime()`, not from the phone's clock; in ViewModels the clock is injected (`elapsedRealtime`).

## Tests
- `./gradlew :core:jvmTest :app:testDebugUnitTest` — unit tests; `:shared:compileKotlinIosArm64` — checks that the iOS code compiles.
- Screens with test data — `shared/.../ui/gallery/Gallery.kt` (`screen("name")`, the `-en` suffix — in English, with Latin
  names via `person()`). They are captured both by Paparazzi tests and by the iOS simulator in Codemagic (`-gallery <name>` in launch
  arguments). A new screen — add it here and to a test.
- Screenshots: `ScreensTest`, `OnlineScreensTest` (Paparazzi 2.0 alpha — 1.3.x doesn't work with compileSdk 36+, Pixel 5). `recordPaparazziDebug` overwrites, `verifyPaparazziDebug` compares.
  Paparazzi doesn't run the main dispatcher: don't use ViewModels that launch coroutines in screenshot tests, or use `Dispatchers.setMain`.
- `LocalGameLaunchTest` — the real `MainActivity` under Robolectric (menu → game, system "Back"): catches what the gallery can't see.
- `GameTimerTest` — the turn timer on a `StandardTestDispatcher` with a fake clock.
- `OnlineE2ETest` — two ViewModels play against the live server; disabled without `E2E=1`.

## Build
iOS: Codemagic (`../codemagic.yaml`): `ios-simulator` — a build without signing or an Apple account (checks Swift/linking);
`ios-testflight` — XcodeGen → signing via the App Store Connect API → TestFlight. The first `./gradlew` run in the Xcode
phase is long (Kotlin/Native). New library versions: Compose 1.12+ requires AGP 9.1+.

Android: `./gradlew assembleRelease` → `app/build/outputs/apk/release/app-release.apk` (R8). Signing — a private release key
kept outside the repository (passwords must never be printed); without it — the debug key.
